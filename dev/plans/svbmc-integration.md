# S-VBMC integration

Execution plan and worklog for bringing the S-VBMC implementation into
PyVBMC. Opened 2026-09-11 on `dev-next` at `e29c5e7`; code work runs on
`dev-svbmc-integration`. The design is the
[integration proposal](../2026-09-08-ecosystem-integration.md), whose open
questions the PI settled on 2026-09-11 as recorded below. Evidence the plan
relies on: the [compatibility report](../results/2026-09-08-svbmc-compatibility.md)
and the [NumPy prototype](../results/2026-09-09-svbmc-numpy-prototype.md).

Source: `acerbilab/svbmc` at `13a78f6c4a3ffe9c4557fee4f4b8f67c98b29e01`
(version 0.1.1), which is still upstream `main` on 2026-09-11. The pinned
checkout used by the earlier studies is the ignored
`dev/scripts/runs/svbmc_compat_20260908/source/`; its `deps/` overlay holds
a CPU Torch 2.14.0 install that this work reuses on `PYTHONPATH` instead of
adding Torch to the repository venv.

## Decisions (PI, 2026-09-11)

- **Backend.** Keep the upstream Torch weight optimizer. Torch stays the
  optional `pyvbmc[torch]` extra, imported lazily; constructing `SVBMC`
  without it raises an `ImportError` naming the extra. Importing `pyvbmc`
  or `pyvbmc.svbmc` never imports Torch.
- **Location and public surface.** `pyvbmc/svbmc/` with `SVBMC` in
  `svbmc.py` and the two helpers (`overlay_corner_plot`,
  `find_init_bounds`) in `utils.py`; `from pyvbmc import SVBMC` resolves
  lazily. The toy targets (`GMM`, `Ring`) do not move: they are example
  material and stay in the standalone package. The PyVBMC example defines
  its target inline.
- **Sampling semantics.** `sample(n)` returns independent draws from the
  stacked mixture: per-run counts drawn from a multinomial over the run
  shares, PyVBMC's random component choice within each run, rows randomly
  permuted. Always exactly `n` rows. `balance_flag=True` gives the
  stratified alternative: exact proportional split across runs with a
  randomized remainder, the flag passed through to each run's sampler.
  Upstream's fixed proportional allocation with independent rounding is
  replaced.
- **Randomness.** A `seed=None` constructor argument replaces upstream's
  `testing` flag, following `VBMC(seed=)`: one generator from `get_rng`
  drives the entropy Monte Carlo draws, the multinomial counts, the
  per-run draws (the copies made in `sample` receive the stacked object's
  generator, so input posteriors are never advanced) and the permutation.
  `seed=None` derives from NumPy's global state, so seeding it beforehand
  still fixes a run.
- **Dtype.** Explicit float64 tensors everywhere; Torch's global default
  dtype is never read or set. The tensor-returning methods (`stacked_ELBO`,
  `maximize_ELBO`) return float64.
- **Shapes.** Component draws canonicalized to `(n_samples, D)` (fixes the
  D=1 failure); copied run weights kept `(1, K)`.
- **Validation and messages.** Reject an empty list, mismatched `D`,
  malformed component shapes, and missing or nonfinite `stable`, `elbo`,
  `I_sk`, `J_sjk`. Argument misuse warns through `warnings.warn`; progress
  goes through `logging` (`pyvbmc.svbmc` logger) like `VBMC`.
- **Fixtures.** No pickles. The thirty upstream posteriors are converted to
  the oracle snapshot format (`.npz` arrays plus JSON tree, rebuilt through
  public constructors) and shipped under `pyvbmc/testing/svbmc/fixtures/`.
  The corpus is entirely unbounded D=2 with identity transforms, so a
  supplementary set generated by short seeded VBMC runs adds D=1, bounded
  D=2 with two runs using different plausible bounds, and D=3 with a
  rotoscale warp. Regression references (weights, ELBO, entropy of a
  seeded short optimization) pin the numerics for the later performance
  change.
- **Compatibility release.** A forwarding `svbmc` release depending on
  `pyvbmc[torch]>=1.5` is prepared and published only after PyVBMC 1.5
  is on PyPI. It forwards `svbmc.SVBMC`, `svbmc.svbmc.SVBMC` and
  `svbmc.utils`, keeps its own `targets`, maps `testing=True` to a fixed
  seed with a deprecation warning, and reports its own `__version__`.
  Out of scope for this plan.
- **Deferred.** The shared-preparation and vectorized-entropy speedups
  measured in the prototype are a separate change after this plan.

## Layout

```
pyvbmc/svbmc/__init__.py          SVBMC, utils re-export
pyvbmc/svbmc/svbmc.py             SVBMC (S-VBMC 2025 BSD notice retained)
pyvbmc/svbmc/utils.py             overlay_corner_plot, find_init_bounds
pyvbmc/testing/svbmc/             tests, fixtures/, FIXTURES.md
dev/scripts/make_svbmc_fixtures.py   pickle -> snapshot conversion; supplementary runs; references
dev/scripts/svbmc_parity_check.py    moved code vs pinned upstream on matched draws
docsrc/source/api/classes/svbmc.rst  API page
examples/pyvbmc_example_7_stacking.ipynb (+ scripts/pyvbmc_example_7_full_code.py)
```

`pyproject.toml` enumerates packages explicitly, so `pyvbmc.svbmc` is
added there, and the fixture globs go into `MANIFEST.in`.
