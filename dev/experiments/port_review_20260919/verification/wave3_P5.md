## Errors found in the reviewers' reports

1. **P5i F7 title and body**: "Ten of the thirteen accepted `gp_mean_fun` names". The list at `vbmc.py:1103-1116` has **twelve** names and **nine** of them fail in the helper (`p5_8_gp_mean_fun.py`). The conclusion stands.
2. **P5c F17**: "`np.argsort(gp.y, axis=None)[::-1]` reverses a stable ascending sort, so among equal `y` values the later index comes first". numpy's default `argsort` kind is `quicksort`, which is **not** stable, so the Python tie order is neither MATLAB's nor the reversed-stable one (`p5_15_tie_order.py` shows all three differing on one five-element vector). The finding itself is confirmed and, if anything, stronger than stated.
3. **P5c F3 and P5i F6**, the `-inf` lower length-scale bound at `:370`: presented as a bound PyVBMC installs where MATLAB leaves the entry unset. It is never installed — the `SquaredExponential` block at `:399-402` replaces the whole tuple, and the value is written only when `upper_gp_length_factor > 0` (row P5-6b). The noise half of the same finding is real.
4. **P5c F10**: "it binds around `n_eff > 1.45 * 1e3`" and "crossing zero at about `x = 1.45`". The cubic is `f(x) = 64 + 960(1-x)^3`; the 9-clamp binds at `x = 1.386` (`n_eff ≈ 1382` at `D = 2`) and the zero crossing is `x = 1.4055` (`n_eff ≈ 1401`). The finding stands. The report also omits the `budget_active` branch (`:628-637`), which clips `x` to `[0,1]` and so closes the clamp off entirely for a charged or precomputed run.
5. **P5c F12**: the title says "Five of the six accepted values cannot run", the body "six of the seven values raise rather than fall back". Neither is exact: `laplace` runs (as slice sampling) while `n_eff < 30`, and `covsample` runs once a usable covariance exists and the threshold test fails. What is exactly true is that each of the six non-`slicesample` values raises at some point in a run, and that `covsample` raises on the *first* fit only because of the fall-through defect.
6. **P5c section 4, defect 1**: "the `slicelite` burn-in is `Inf` or `NaN`". In the branch's own reachable region (`rindex < 1`) MATLAB's expression yields `1`, not `Inf` or `NaN`; the real complaint is that the formula collapses to its floor at the default threshold.
7. **P5c section 4, defect 3**: "`hypcov` comes back a `0x0` matrix rather than `[]`; the caller's `~isempty(hypcov)` test then passes". `zeros(0,0)` *is* empty in MATLAB, so the test fails and the caller behaves correctly; and the state needs `TolCovWeight > 1`, far off the default `0`.
8. **P5c section 4, defect 4**: the two tests are not redundant — `all(isfinite(widthmult))` is what implements the documented `GPSampleWidths = Inf` ("do not use previous widths") setting.
9. **P5c test note**: "No test at all covers … `reupdate_gp`" — `test_vbmc_active_sample.py:1949` calls it and asserts against its output.
10. **P5c test note**: "`test_gp_hyp` … asserts exactly one number" — it asserts two.
11. **P5i test note**: "with the identity-ish transform of that fixture it does not matter" (the bounds `test_gp_hyp` passes) — the transformed and untransformed plausible boxes differ by a factor of four in width in that fixture.
12. **P5i F1 minor**: "the option … is documented in `advanced_vbmc_options.ini:243`" and "its description is asserted verbatim by `test_options.py:427`" — both correct; recorded here only because I checked them (the assertion is inside the parametrized `test_shipped_descriptions_are_stored_in_full`).
13. **Not in either report** (small, Python-only): the `gp_mean_fun` error message at `vbmc.py:1120-1123` misspells `negquad` as `egquad`; the underlying text, "Supported mean functions are zero, const, negquad, and se" beside a twelve-name list, is wrong on both sides (`misc/setupvars_vbmc.m:289-290`).

Everything else I checked in the two reports — the quoted code, the line numbers (which all held at `befab5d9`), the MATLAB references, the option defaults (I confirmed that `TolCovWeight`, `GPSampleWidths`, `CovSampleThresh`, `GPRetrainThreshold`, `WeightedHypCov`, `HypRunWeight`, `GPHypSampler`, `UpperGPLengthFactor`, `GPTrainNinit`/`Final` and `StableGPSamples` are identical on both sides) — held up.
