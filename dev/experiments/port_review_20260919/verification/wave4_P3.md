## Errors found in the reviewers' reports

1. **P3c F3**: "PyVBMC and MATLAB **both** require an integer variable's hard bounds to sit at half-integers and to be finite." MATLAB does not. `misc/setupvars_vbmc.m:19-21` reduces to a finiteness test, which is entry 10 of `matlab_side_defects.md` and an entry of the known-differences sheet the reviewer was given (`:721-734`). The rest of the finding stands.
2. **P3c F3**: "I found no path that produces [an exact half-integer] systematically." There is one, contrived but deterministic: with the default probit transform and an integer variable whose box has an even number of levels, the box midpoint is a half-integer and the transformed value `0.0` maps back to it exactly, so a starting point at the box midpoint enters the sieve as an exact tie through the cache branch of `_get_search_points`. Conversely the reviewer under-states one protection: the hard bounds themselves *are* half-integers and the inverse transform saturates onto them, but `active_sample.py:1072` clips every candidate to the finite transformed search box, so they are never reached.
3. **P3i F9**: "`np.argmin` over an all-`nan` array returns index 0, so `active_sample.py:435` would silently take the first sieve candidate", and "Verified for all five values". 5. **P3c F2, test-adequacy note**: "`norm.cdf(0.6745) = 0.7500029`". It is `0.7500032571`. The conclusion (the assertions would still pass) is unaffected.
6. **P3i F4**: the finding proposes "possibly intentional" without being able to say what MATLAB does. MATLAB averages identically (`private/activesample_vbmc.m:174`), so the classification is "shared by design", and the paper's appendix §C.1 supports the single-value design.
