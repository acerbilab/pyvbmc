## Errors found in the reviewers' reports

**P7 internal.**
1. **F14** presents the `n/(n−1)` normalization as a property of `kde_1d` measured against its own docstring. `shared/kde1d.m` has exactly the same property — the two grid sums agree to 1e-15 at `n = 2^10`, `2^12` and `2^14`. It is shared with MATLAB, not a Python peculiarity, and the finding's "possibly intentional" classification should be "shared by design".
2. **F4** reads the absolute `√eps` box offset as a Python choice that "should scale with the range". `vbmc_mode.m:39-40` uses the same absolute `sqrt(eps)`, so the criticism applies to MATLAB equally. (The report is on the internal track and did not read MATLAB; the finding as written nonetheless implies a Python-only decision.)
3. **F4**, second half: "relies on L-BFGS-B silently re-clipping it" is right, and the consequence is nil — the re-clip lands on exactly the point MATLAB's own clamp produces, because MATLAB clamps to the shrunken box it passes to `fmincon`.
4. **F5** treats "the cache ignores `n_opts`" as a defect. `vbmc_mode.m:18` ignores `nmax` in the same way. What is genuinely Python-only is that `get_parameters` does not clear the cache (`misc/rescale_params.m:39-40` does, "The mode may have moved") and that the mode is stored unconditionally (MATLAB stores it only when a second output is requested).
5. **F7**: "The two coincide only when `D*K` happens to equal the tail length." The only flag combination at which the coded and the intended slice agree is `mu`-only, where both inspect the whole vector. The report also does not name the case that makes the guard vacuous: whenever `optimize_mu` is False the coded slice is **empty**.
6. **F12(c)** presents the negative-`df` asymmetry between `pdf` and `sample` as a Python inconsistency. `vbmc_pdf.m:87-102` supports the family and `vbmc_rnd.m` does not; the asymmetry is MATLAB's, and only the failure mode differs (a Python `ValueError` against a MATLAB matrix of `NaN`).
7. **F15**: the disagreement between the two entropies at `K = 1` is real and **shared** — `ent/entlb_vbmc.m:45-47` returns 0 and `ent/entmc_vbmc.m:96-101` returns `H − 1`.

True of `f873556`, not of the present code: `799852a` (2026-09-20) gives such a row log weight `−inf`, and the block now sits at `:351-395`.
